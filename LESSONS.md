One line per lesson. That is the whole format, and the brevity is the point.

These lines are the cross-project learning surface: a new project starts by
reading what the last few projects taught, and the hub collects them from every
project repo. A paragraph does not survive that trip. A line does.

Write a lesson the moment it is learned, not at close. The close is where you
pick the single best one for `lesson:` in project.md frontmatter.

What counts as a lesson:
  - Something that cost time and will cost it again. "JLC rejected the zip
    because the outline was .gko not .gm1."
  - A rule of thumb that turned out to be wrong here, and the boundary.
  - A tool behaving differently than documented, with the version.
  - A part, vendor, or process that worked or did not, specifically.

What does NOT belong here:
  - Project status. That is worklog.md.
  - Why the design is the way it is. That is protoboard/docs/decisions.md.
  - Anything that only makes sense with the project open. If the line does
    not help someone who never saw this project, rewrite it or drop it.

Promotion rule: a one-off stays here. If the same lesson shows up in a second
project, it has stopped being a lesson and become a protocol or skill fix -
file it so nobody learns it a third time.
